Digital CMOS Standard-Cell Library & Hierarchical Custom Layout

An 11-track standard-cell library, hierarchical digital blocks, and a 6T SRAM bitcell and array in SAED 28/32 nm

Synopsys Custom Compiler · IC Validator · StarRC · PrimeWave · SAED 28/32 nm

Role in the project

Sole author: logic definition and Boolean analysis, transistor-level schematic design, symbol and testbench development, full-custom layout, DRC and LVS closure in IC Validator, parasitic extraction in StarRC, and post-layout simulation and performance analysis in PrimeWave.

Objective

Build a place-and-route-compatible standard-cell library from the transistor level up, then use those cells as the foundation for hierarchical digital blocks — so the same design decisions can be traced from a single gate through to a multi-block structure.

Standard-cell library

Eight cells at a consistent 11-track height: INV, BUF, NAND2, NOR2, AND2, OR2, XOR2, XNOR2.

  • Consistent cell height and aligned VDD/VSS rails so cells abut cleanly in a placement row.
  • Diffusion sharing between adjacent devices to cut active area and junction capacitance.
  • Euler-path optimisation where the logic function permitted an uninterrupted diffusion strip.
  • Pin-access planning so router access to every pin exists from the expected metal layer.
  • Cell abutment verified by tiling cells side by side and re-running DRC on the assembled row.

Hierarchical digital blocks

Built from the cell library and from custom transistor-level structures:

  • Transmission-gate logic: inverter, AND, OR, NAND, NOR, XOR, XNOR, multiplexer, demultiplexer.
  • Combinational arithmetic: half and full adders, half and full subtractors, decoders, encoders.
  • Sequential circuits: D and T flip-flops, master–slave and edge-triggered architectures.
  • A 4-bit asynchronous counter built from the custom sequential blocks.
  • 8:1 serializer and 1:8 deserializer structures.

How layout decisions affect behaviour

  • Parasitic capacitance — diffusion sharing and shorter internal routing reduce the capacitance a driving stage sees.
  • Delay — that capacitance, together with device sizing, sets the cell's propagation delay; post-layout delay is what actually matters, not the schematic figure.
  • Power — dynamic power scales with the switched capacitance, so layout compaction reduces it directly.
  • Signal integrity — adjacent parallel routing introduces coupling; spacing and layer choice manage it.
  • Cell abutment and routability — rail alignment and pin placement determine whether the library is usable in an automated flow at all.

Featured sub-project — 6T SRAM Bitcell & Array

A cross-coupled 6T bitcell built as a tileable unit, then replicated into an array with shared rails, word-line distribution, and differential bit-lines.

SRAM timing, static noise margin, and power figures are not claimed — those characterisation results are not part of the documented result set.

Circuit structure

  • Cross-coupled inverter pair forming the bistable storage element.
  • Access transistors connecting the storage nodes to the differential bit-lines, gated by the word line.
  • Device ratios — the relative strength of pull-down, access, and pull-up devices governs whether the cell can be read without disturbing its state and written when required.

Layout and array organisation

  • Symmetry between the two storage halves so both states behave identically, maintained through contact and via placement rather than device placement alone.
  • Shared supply rails across abutting cells, with mirrored tiling to share contacts and diffusion at the cell boundaries.
  • Word-line distribution across the row and differential bit-lines down the column.
  • Bit-line parasitics — capacitance grows with array height and directly affects read behaviour, so column routing was kept tight and balanced between BL and BLB.

Verification flow

Bitcell layout→DRC→LVS→Array tiling→Array DRC / LVS / ERC→PEX→Correlation

Design flow

Logic definition→Schematic→Symbol + testbench→Pre-layout sim→Layout→DRC→LVS→PEX→Post-layout sim→Timing / power / area

Verification

DRC and LVS closed in Synopsys IC Validator, parasitics extracted with StarRC, and pre-layout versus post-layout behaviour correlated in PrimeWave.

Key learnings

  • A cell library is an interface contract; height, rails, and pin access matter more than clever internal tricks.
  • Euler-path ordering is worth the effort exactly when it removes a diffusion break.
  • The post-layout number is the real number — schematic timing is an estimate.
