VLSI course project

Neural Network-Based Video Processing Block for Color Detection

VLSI implementation of a real-time color-detection block, from behavioural architecture to verified layout

Cadence Virtuoso · Verilog HDL · Xcelium · FPGA-oriented architecture

Role in the project

COMPE572 VLSI Circuit Design, Fall 2024. A team course project delivered in three graded phases; my contribution covered architecture and behavioural modelling, transistor-level design of assigned sub-blocks, floorplanning input, physical layout, and verification.

Course project. The architecture is synthesizable and FPGA-oriented; it was not fabricated, and no silicon or FPGA measurement results are claimed.

Objective

Implement a video-processing block that performs real-time color detection using a neural network, with an architecture chosen to remain synthesizable rather than only behaviourally correct.

Design flow

Behavioural architecture→Verilog modelling→Schematic design→Floorplanning→Layout→Integration→Verification

Phase 1 — system design and modelling

  • Defined the target architecture and its functional blocks.
  • Created the top-level Cadence symbol and design hierarchy.
  • Performed high-level modelling in Verilog HDL.
  • Simulated the architecture in Virtuoso and Xcelium.
  • Defined block-level design responsibilities and the delivery schedule.

Phase 2 — schematic design and floorplanning

  • Designed key transistor-level sub-blocks.
  • Performed schematic-level validation against the behavioural model.
  • Completed system floorplanning.
  • Defined the I/O layout and routing strategy.

Phase 3 — layout, integration, and validation

  • Completed the physical layouts for the assigned blocks.
  • Ran block-level and system-level DRC and LVS.
  • Integrated the sub-blocks into the top-level design.
  • Simulated the extracted netlist.
  • Compared schematic and post-layout behaviour.

Key learnings

  • An algorithm becomes a chip only once its architecture is constrained to what hardware can build.
  • Block ownership across a team makes interface definition the highest-risk part of the schedule.
  • Post-layout comparison catches integration errors that block-level verification passes over.
